# Persistenzstrategie für Walking Skeleton (Sprint 1)

**Status:** Akzeptiert 

## Kontext
Persistenz für SSA-eigene Daten

## Entscheidung
Für das walking Skeleton beschränken wir uns auf ein Terminal, deshalb werden die Daten (wie Vorbestellungen, Warteliste usw.) hier lokal abgelegt (also auch "Modulith"-Architektur). Der Port ist und bleibt lokal, die Daten später an einer zentralen Instanz.

## Konsequenzen
* **Gut:** einfach, reicht aus, um den kompleten Prozess sofort umsetzen und damit die Anforderungen und Architektur validieren.
* **Schlecht / Risiko:** Manche NFRs (keine zwei gleichzeitigen Anmeldungen usw.) können so nicht validiert werden.
